# Story 4.8.6: Frontend - Testes de Resiliência e Reconexão de Sessão

*   **Status:** `Done`
*   **Epic:** `4: O Copiloto Inteligente com Agentes Dinâmicos`

## Story

**Como um** usuário do chat,
**Eu quero** que a conexão com o backend seja resiliente e se reconecte automaticamente à minha sessão ativa em caso de queda,
**Para que** eu não perca o contexto da minha conversa e possa continuar meu trabalho sem interrupções ou perda de dados.

## Acceptance Criteria

1.  **Detecção de Queda:** O frontend DEVE detectar de forma confiável quando a conexão com o backend (serviço Claude Code) é perdida.
2.  **Tentativa de Reconexão Automática:** Ao detectar a queda, o frontend DEVE iniciar um processo de reconexão automática sem a necessidade de intervenção do usuário.
3.  **Feedback Visual:** O usuário DEVE receber um feedback visual claro na interface indicando o status da conexão (ex: "Conectado", "Conexão perdida, tentando reconectar...", "Falha na reconexão").
4.  **Preservação da Sessão:** Após a reconexão bem-sucedida, o frontend DEVE restabelecer a comunicação na **mesma sessão** anterior, preservando todo o histórico de chat e o contexto atual. Uma nova sessão NÃO DEVE ser criada.
5.  **Estratégia de Backoff:** A lógica de reconexão DEVE implementar uma estratégia de exponential backoff para evitar sobrecarregar o servidor com tentativas excessivas em caso de falha persistente.
6.  **Falha Definitiva:** Se a reconexão falhar após um número configurável de tentativas, o frontend DEVE parar de tentar e informar ao usuário que a conexão não pôde ser restabelecida, oferecendo uma opção para tentar novamente de forma manual.
7.  **Múltiplas Sessões:** O mecanismo de reconexão deve funcionar de forma independente para cada sessão aberta em abas diferentes, sem interferir umas nas outras.
8.  **Conexão Estável:** A conexão DEVE permanecer ativa por pelo menos 1 minuto de inatividade sem ser encerrada pelo frontend ou backend.

## Dev Notes

*   A principal causa do bug é que, ao ocorrer uma interrupção na comunicação, o estado da sessão não é preservado e uma nova sessão é iniciada implicitamente. A solução deve focar em gerenciar o ciclo de vida da conexão ativamente no frontend.
*   A lógica de reconexão deve ser cuidadosamente implementada para lidar com o ID da sessão. O frontend deve armazenar o ID da sessão ativa e reenviá-lo ao backend a cada tentativa de reconexão para garantir a continuidade.
*   Referenciar a história `4.5` para entender como o backend gerencia os arquivos de sessão. A reconexão não deve causar escritas ou exclusões indevidas nesses arquivos.
*   A biblioteca de comunicação com o backend (provavelmente usando WebSockets) deve ser investigada para identificar os melhores hooks para monitorar o estado da conexão.
*   A conexão pode estar sendo encerrada por um timeout no lado do servidor ou do cliente. É preciso verificar as configurações de ambos.

### Testing Scenarios
*   **Cenário de Teste 1: Queda e Reconexão com Sucesso**
    1.  Inicie uma sessão e envie algumas mensagens.
    2.  Simule uma queda de rede (desconecte o Wi-Fi ou use ferramentas do navegador).
    3.  Verifique se o indicador de "conexão perdida" aparece.
    4.  Restaure a conexão.
    5.  Verifique se o frontend reconecta automaticamente, o indicador mostra "conectado" e o histórico da sessão está intacto.
    6.  Envie uma nova mensagem e confirme que ela é adicionada à mesma sessão.
*   **Cenário de Teste 2: Falha Persistente de Conexão**
    1.  Inicie uma sessão.
    2.  Simule uma queda de rede permanente (mantenha o servidor de backend offline).
    3.  Verifique se o frontend tenta reconectar com intervalos crescentes (exponential backoff).
    4.  Verifique se, após o número máximo de tentativas, ele para e exibe uma mensagem de falha permanente.
*   **Cenário de Teste 3: Múltiplas Sessões**
    1.  Abra duas sessões diferentes em duas abas do navegador.
    2.  Derrube a conexão de apenas uma delas.
    3.  Verifique se apenas a aba afetada tenta reconectar, enquanto a outra permanece funcional (se a conexão for por aba).
    4.  Restaure a conexão e valide a integridade de ambas as sessões.
*   **Cenário de Teste 4: Estabilidade da Conexão**
    1.  Inicie uma sessão.
    2.  Não envie nenhuma mensagem.
    3.  Verifique se a conexão permanece aberta por pelo menos 2 minutos sem ser encerrada.
    4.  Envie uma mensagem e verifique se ela é recebida com sucesso.
